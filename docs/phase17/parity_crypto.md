## Gaps summary

**BatchVerifier mechanism absent (out-of-scope), but the malleability-edge-case vectors were a genuine consensus-correctness bug — now fixed (issue #1136, 13 tests: all of `batchverifier_test.go`, `gobatchverifier_test.go`).** algod-rust has no ed25519 *cryptographic* batch-verification abstraction (combining N checks into one accelerated computation) anywhere in `crates/` — it verifies signatures individually, but concurrently across tokio tasks, a different parallelization strategy for the same throughput goal (`out-of-scope`, 9 of the 13 tests). The remaining 4 (`TestBatchVerifierTamingEdDSAsEdgeCases`/`TestBatchVerifierEd25519ConsensusTestData`/`TestBatchVerifierLibsodiumTestData`/`TestBatchVerifierFilippoVectors`) are ed25519 *malleability* edge-case vectors, not batching-mechanism tests — go's single-signature verify deliberately calls libsodium's `bv_compatible` entry point specifically to stay acceptance-consistent with its batch verifier (avoiding a single-vs-batch consensus fork risk). Porting all four vector suites and running them through `signature.rs`'s actual production verify path confirmed `ed25519_dalek::Verifier::verify()`'s default ruleset genuinely diverged from `bv_compatible`: it is *cofactorless* (go's `bv_compatible` is *cofactored*) and never rejects a small-order public key (go's does). This meant algod-rust would have wrongly REJECTED some signatures go-algorand accepts (not the more dangerous "accepts what go rejects" direction, but still a real cross-implementation parity bug). Fixed by implementing `bv_compatible`'s exact ruleset directly against `curve25519-dalek` primitives (`ed25519_bv_compatible_verify` in `signature.rs`), used consistently at every ed25519 verify call site in that module (single-sig, multisig subsigs, LogicSig delegated sig, heartbeat proofs). All four vector suites (12 Taming-EdDSA + 196 "It's 255:19am" cartesian + 54-of-768 Filippo representative + 10-of-1025 libsodium sanity) now pass against the fixed production verify path, and a dedicated regression test reproduces the pre-fix divergence directly against plain `ed25519_dalek::verify()` as a permanent witness.
