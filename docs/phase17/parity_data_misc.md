## Gaps summary

- **Application-call excessive-rate-limiter (ERL) subsystem** (`data/appRateLimiter.go`, `TestAppRateLimiter_*`, and `TestTxHandlerAppRateLimiter*`/`TestTxHandlerERLIPClient`/`TestTxHandlerErlClientMapper`/`TestTxHandlerCapGuard` in `txHandler_test.go`): the *algorithm* is ported standalone (issue #821, PR #890, `crates/core/algo-pool/src/app_rate_limiter.rs`, all `TestAppRateLimiter_*` rows above), but no wiring into a live admission path exists. The REST submission path was investigated as a possible non-network wiring point and found not to correspond to any real go-algorand mechanism — go never applies ARL/ERL to REST-submitted transactions (`RawTransaction`/`RawTransactionAsync` both bypass `TxHandler`'s rate-limit checks) — so it was deliberately not wired. The only faithful wiring point remains the pull-based tx-syncer peer path, which needs the architectural push-vs-pull redesign this issue already flags as separate follow-up work; no per-app/per-IP rate limiting is enforced by algod-rust today.
- **go's push-based gossip `TxHandler`** (`data/txHandler_test.go`, `data/txDupCache_test.go`) has no 1:1 counterpart: algod-rust ingests transactions through a pull-based tx-sync design (`crates/node/algo-network/src/tx_syncer.rs`, `tx_sync_pool_adapter.rs`, `tx_sync_client.rs`) with a different seen-cache/backlog model, so message censoring, backlog-drop, salted-cache-rotation, and CapGuard tests have no corresponding rust tests.
- **`basics.Fraction`** (rational-number type, `fraction_test.go`) and **`basics.SError`** (structured/annotatable error type, `serr_test.go`) have no rust equivalents; algod-rust uses `thiserror`/`anyhow` idioms instead of a shared structured-error type.
- **`data/hashable.Message`** and **`data/stateproofmsg.Message`** msgpack roundtrip tests have no located rust equivalents.
- Several **participation-registry SQLite-internals tests** (`TestFlushDeadlock`, `TestFlushResetsLastError`, `TestParticipationDB_Locking`, `TestRegisterUpdatedEvent`, `TestAddingSecretTwice`) reflect go's specific SQLite-flush-goroutine/event-subscription implementation details that algod-rust's participation store (`crates/core/algo-ledger/src/participation/`) does not model the same way; most are `not-implemented` or `missing-test`.
- **`StateSchema`/`StateSchemas`, `ParticipationUpdates`, `BlockHeader`(direct), and `LightBlockHeader` msgpack-roundtrip tests** are `missing-test`: the underlying types exist in algod-rust but no dedicated round-trip unit test was located (though related behavior is covered indirectly through canonical-encoding, genesis, and light-header-proof API tests).
- go's **reflection-based struct-field audits** (`TestBlockFields`, `TestAccountDataFields`) and **test-utility helpers** (`TestNearZeros`/`TestUnexported`/`TestMap` in `basics/testing`, `TestPow` in `txHandler_test.go`, `TestParticipationDB_Locking`) are `out-of-scope` — they exercise go-specific reflection or test-infra rather than portable protocol behavior.
- **Pool-error sub-classification tests** (`TestPoolLeaseReevalClassification`, `TestPoolAssetBalanceClassification`, `TestPoolTealRejectClassification`, `TestPoolTealErrClassification`) are only `partial`-matched: algod-rust's `algo-pool/tests/conformance_test.rs::test_pool_error_classification` covers general error-tag classification but not each specific rejection category individually.
- **Close-account-through-pool tests** (`TestCloseAccount`, `TestCloseAccountWhileTxIsPending`, `TestCloseToAccountBelowMinBalance`) are `missing-test` in `crates/core/algo-pool`.
