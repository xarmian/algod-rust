## Gaps summary

- **Static type-tracking pass is entirely absent from algod-rust's assembler.** Roughly 15 go tests (`TestBranchAssemblyTypeCheck`, `TestSwapTypeCheck`, `TestEqualsTypeCheck`, `TestDupTypeCheck`, `TestSelectTypeCheck`, `TestSetBitTypeCheck`, `TestScratchTypeCheck`, `TestScratchBounds`, `TestTypeTracking`, `TestTypeTrackingRegression`, `TestMatchTyping`, `TestTxTypes`, `TestArgType`, `TestTypeComplaints`, `TestDupPopNTyping`) all depend on go's compile-time stack-type inference; algod-rust's assembler does no such analysis. This is a real, large functionality gap, not just a test gap — worth its own issue.
- ~~**`match` opcode (v8) is implemented but has zero execution-level tests.**~~ **Fixed** in issue #823 (PR #848) for `TestMatch`/`TestShortMatch` — this also exposed and fixed a real `op_match` stack-pop-order bug. The opcode's assembler-level and malformed-bytecode disassembly paths remain untested (`TestAssembleMatch`, `TestDisassembleBadMatch`, `TestShortSwitch`, `TestDisassembleBadSwitch`, `TestDisassembleBadMultiOp`, `TestDisassembleBadBranch`).
- ~~`RekeyTo`/`ApplicationCall`-raises-minimum-AVM-version rule appears unimplemented.~~ **Fixed** in issue #811 (PR #831): `AvmContext::min_avm_version` + `validator::check_min_avm_version`.
- **go's macro/preprocessor and pseudo-op aliasing features are absent.** `#define` macro expansion (`TestMacros`), automatic `txn`/`gtxn` → `txna`/`gtxna` aliasing (`TestAssembleAlias`, `TestDisassembleTxna`, `TestDisassembleGtxna`), and the `replace` pseudo-op auto-selecting replace2/replace3 (`TestReplacePseudo`) all have no rust equivalent.
- **Assembler-time error-message/immediate-validation coverage is thin.** ~~`TestAssembleArg`, `TestBranchArgs`, `TestSeveralErrors`, `TestAssembleRejectDupLabel`~~ **fixed** in issue #823 theme 4 (PR #854). `TestAssembleTxna`, `TestAssembleConstants`, `TestAssembleBranchTooFar`, `TestReportMultipleErrors`, `TestAssembleDisassembleErrors` remain untested — `TestAssembleTxna` in particular may be a real feature gap (algod-rust's field-immediate resolution doesn't appear to special-case the 1-vs-2-vs-3-immediate `txn`/`gtxn`/`txna`/`gtxna` arity variants the way go's assembler does), not just a missing test.
- **Exhaustive per-version/whole-table completeness sweeps are only spot-checked.** go repeatedly asserts *every* opcode/field in a version's table is correctly gated (`TestAllowedOpcodesV2`, `TestAllowedOpcodesV3`, `TestOpcodesByVersion`, `TestOpcodesVersioningV2`, `TestBackwardCompatGlobalFields`, `TestBackwardCompatTxnFields`, `TestGlobalVersionsAndTypes`, `TestTxnFieldVersions`, `TestITxnFieldVersions`, `TestAssetParamsFieldsVersions`, `TestAppParamsGetFieldsVersions`/`SetFieldsVersions`, `TestAcctParamsFieldsVersions`, `TestBlockFieldsVersions`); algod-rust has individual `version_gate_*_requires_vN` tests per opcode/field but no single sweep guaranteeing completeness as new opcodes/fields are added — a regression risk worth a consolidated "table completeness" test-infrastructure issue.
- ~~**JSON parser (`json_ref`/`parseJSON`) edge-case parity is under-tested.**~~ **Fixed** in issue #823 theme 2 (PR #851) for 10 of the ~13 `jsonspec_test.go` cases (trailing commas, comments, BOM, control chars, escape sequences, big-number precision including `TestParseBigNum`'s 2^64-1 case, hex literals, whitespace rules, special numeric values, UTF-16LE rejection) -- all passed against the existing implementation with no code changes needed. `TestParseArrays`'s leading-comma-in-array/nested-array cases, and the UTF-16BE/UTF-32 variants of `TestParseFileEncoding`, remain untested.
- **Box-storage budget/dirty-tracking/cross-txn mechanics are implemented but largely untested.** ~~Dirty-byte tracking (`TestDirtyTracking`) and repeated-create no-op behavior (`TestBoxRepeatedCreate`)~~ **fixed** in issue #823 theme 3 (PR #852). Write-budget enforcement's remaining specific scenarios (`TestBoxWriteBudget`, `TestWriteBudgetPut`), I/O-budget growth from empty BoxRefs (`TestIOBudgetGrow`), ClearState box-access prohibition (`TestBoxUnavailableWithClearState`), and cross-txn box visibility within a group (`TestBoxAcrossTxns`) remain untested.
- **Resource-sharing/foreign-array error-message granularity is narrower than go's.** go distinguishes several specific "not available" error messages for locals/holdings access across a group (`TestBetterLocalErrors`, `TestBetterHoldingErrors`), which aren't confirmed replicated, though the underlying availability logic exists.
- **Several EC/pairing and crypto cost/edge-case tests are only partially covered**: `TestPairCheck`/`TestEcMultiExp` cover only BN254 (not BLS12-381); `TestMapTo`/`TestSlowMapTo` cover only BN254 G1/G2 (not BLS12-381) -- these two remain open. ~~`TestEcdsaCostVariation`/`TestHashCosts`/`TestLeadingZeros` have no dedicated cost/edge-case test despite the opcodes being implemented.~~ **Fixed** in issue #823 theme 5 (PR #853).
- **Go-runtime-specific mechanisms correctly marked out-of-scope**: panic/recover-based error handling (`TestPanic`, `TestEvalPanicWithTracer`, `TestEvalWithTracerPanic`), internal doc-generation tables (`doc_test.go`, most of `opcodes_test.go`), internal helper-API unit tests with no rust analog (`TestArgType`, `TestIsPrimitive`, `TestTxnFieldToTealValue`, `TestUint128`, `TestBlankStackSufficient`), and go's own tokenizer/macro-expansion internals (`TestTokensFromLine`, `TestNextStatement`).
