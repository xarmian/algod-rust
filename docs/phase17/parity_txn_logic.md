## Gaps summary

- ~~**Static type-tracking pass is entirely absent from algod-rust's assembler.**~~ [Issue #829](https://github.com/xarmian/algod-rust/issues/829)'s first incremental slice added a static stack-type-tracking pass (`crates/core/algo-avm/src/type_track.rs`) covering straight-line (branch-free) instruction sequences: fixed-proto arithmetic/logic/comparison opcodes, literal pushes, and the stack-shuffling opcodes whose return type is data-dependent (`swap`, `dup`, `dup2`, `select`, `setbit`, `dig`, `==`/`!=`) — fixing `TestSwapTypeCheck`, `TestEqualsTypeCheck`, `TestDupTypeCheck`, `TestSelectTypeCheck`, `TestSetBitTypeCheck`, and the first case of `TestTypeTracking`. Its second incremental slice added **branch-merge type unification** (mirroring go's `ProgramKnowledge.deadcode`/`bottom` state exactly: `b`/`callsub`/`retsub`/`err`/`return` mark everything until the next label as dead code, and a label reached through dead code reopens analysis permissively, while a label reached by ordinary fallthrough — e.g. right after a conditional `bnz`/`bz` — doesn't reset anything) — fixing `TestBranchAssemblyTypeCheck`, `TestTypeTrackingRegression`, and the rest of `TestTypeTracking`. Its third incremental slice added **scratch-slot per-index type tracking** (`OpStream::scratch_space`, mirroring go's `ProgramKnowledge.scratchSpace`, plus a narrow `OpStream::type_stack_const` for recognizing a literal `int` index under `loads`/`stores`, mirroring go's `StackType.constInt()`) — fixing `TestScratchTypeCheck` and `TestScratchBounds`'s message-observable case. Its fifth incremental slice added type-tracking for the **fixed-immediate-arity opcodes** `popn`/`dupn`/`cover`/`uncover` (ports go's `typePopN`/`typeDupN`/`typeCover`/`typeUncover`, `assembler.go:1486-1524,1621-1646`, directly — these four read a single immediate byte straight from the bytecode at assembly time, so their pop/push counts are fully known statically) — fixing `TestDupPopNTyping`. Its sixth incremental slice modeled the remaining dispatch-/variable-arity opcodes precisely instead of permanently disabling tracking: **`match`** (pops `N+1` opaque values, `N` = label count, ports go's `typeMatch`), **`pushbytess`/`pushints`** (one `Bytes`/`Uint64` push per literal, ports `typePushBytess`/`typePushInts`), and **`txn`/`gtxn`/`gtxns`/`txna`/`gtxna`/`gtxnsa`** (turned out to need no field-type lookup at all — go's own assembler always pushes an opaque `StackAny` for every one of these six regardless of the accessed field's real type, and every pseudo-op's dispatch arities share one proto, so looking up the pseudo mnemonic itself suffices; `gtxns`/`gtxnsa` additionally pop a typed `Uint64` dynamic transaction index) — fixing `TestMatchTyping`, the final sub-case of `TestAssembleMatch`, and (on inspection) also directly pinning `TestTypeComplaints` (already covered incidentally by slice 2's dead-code handling). Two of the tests originally cited as needing this slice's still-deferred bounds work turned out to be mismatched on closer reading: `TestArgType` is an unrelated runtime `stackValue.avmType()` unit test (already correctly out-of-scope, see its own row), and `TestTxTypes` exclusively exercises `itxn_field`'s field-type refinement, not the `txn`/`gtxn`/`gtxns` read opcodes this slice modeled (see `TestTxTypes`'s own row). Its seventh (final) incremental slice ported **`itxn_field`'s field-type-aware refinement** (go's `typeTxField`, `assembler.go:1532-1541`): the popped value's expected type is refined to the assigned field's own type (`itxn_field_type` in `type_track.rs`, covering every recognized `txn`-family field name) instead of the base proto's opaque `Any` — fixing `TestTxTypes`.
