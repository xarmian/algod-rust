# Phase 17 Test Parity — test/e2e-go

algod-rust's closest structural analog to go-algorand's `test/e2e-go` harness
(real nodes driven by `goal`/`kmd` CLIs over shell scripts) is the
`bin/algod-rust/tests/live_*.rs` family (drives a real algod-rust node, often
cross-checked against a live go-algorand localnet), `crates/tools/goal-rust/tests/*_e2e.rs`
(drives `goal-rust` against real algod/kmd daemons, several `MIXED_CLUSTER`-gated
against **Go's own** algod/kmd), `crates/node/algo-kmd/tests/{interop,rest_interop}_test.rs`
(`MIXED_CLUSTER`-gated cross-impl kmd tests), and `bin/algod-rust/tests/sync_test.rs` /
`p2p_go_algorand_interop.rs`. Everything else in this repo's test suite is
crate-level unit/integration tests that exercise the same ledger-apply,
validation, REST-handler, and simulation logic the go e2e tests exercise
end-to-end, but through direct Rust calls rather than a live multi-node
network — those are marked `partial` rather than `matched-*` unless a
`live_*`/`*_e2e.rs` test drives the actual behavior against a running node.

## Gaps summary

- **Multi-node network scenarios (catchup, partition recovery, incentives, state proofs, participation-over-many-rounds)**: the largest gap category. go's e2e-go harness spins up real multi-node testnets and exercises catchpoint catchup, gossip catchup, network partitions, incentive payouts/suspension/whale-join, and multi-round stateproof signing across many nodes. algod-rust has no equivalent multi-node orchestration test harness — these are `missing-test` even though the underlying unit logic (catchpoint import/cutover, proposer-payout eligibility, voters-round/commitment formulas, keyreg apply) is extensively unit-tested. Building a `MIXED_CLUSTER`-style multi-node algod-rust test harness (extending the existing single-node `live_*`/`*_e2e.rs` pattern) would close most of this.
- **REST API negative/edge-case coverage (bad/missing account or asset/app index, mutated addresses, low-fee/oversized/empty-account send rejections)**: many `restAPI` and `features/transactions` error-path tests have no confirmed Rust counterpart, even though the REST handlers and validation rules exist — these look like straightforward additions to `algo-rest-api/tests/integration.rs` or a new `live_*` test rather than missing functionality.
- **kmd session/config edge cases** (issue #827 theme 2, resolved): `TestWalletSessionExpiry`, `TestNonAbsSQLiteWalletConfigErrs`, `TestMultisigSignWithWrongSigner` are now matched — `config_test.rs::load_rejects_relative_wallets_dir` already covered the sqlite-config case pre-existing; `api_v1.rs::wallet_handle_expires_after_session_lifetime` and `api_v1.rs::multisig_sign_rejects_signer_outside_msig_preimage` add the two HTTP-level scenarios that were genuinely missing.
- **TEAL compile endpoint and Merkle-proof endpoints** (issue #827 theme 3, resolved): `TestTealCompile` was already covered by `teal_compile_*` in `integration.rs` (this row previously pointed at the wrong location — a nonexistent `goal-rust` e2e — and has been corrected). `TestTxnMerkleProof`/`TestTxnMerkleProofSHA256` needed two new tests (`get_transaction_proof_sha256_happy_path`, `get_transaction_proof_sha256_rejected_on_pre_v34_protocol`) since the existing suite only exercised the default sha512_256 hashtype.
- **Legitimately out-of-scope (go CLI/kmd-CLI harness, tcl `expect` scripts, `algoh` health monitor, Go-runtime goroutine-dump debug endpoint, 5M-account/many-account scale scenarios, cross-version live-upgrade tests needing old pinned go-algorand binaries)**: these test go-algorand's own process/CLI tooling, or need infrastructure (old binaries, 5M synthetic accounts) outside this repo's scope — no action needed. (Note: a follower node is no longer out-of-scope — issue #951 landed real follower-node ledger ownership; see `TestSimulateStartRound` below for the one remaining follower-adjacent gap.)
- **Grouped-transaction submission, send/broadcast negative paths, lease-conflict regressions, kmd multisig/keyreg/MDK edge cases** (issue #950 themes 2-3-4-6-7-8, resolved): `TestZeroThreshold`/`TestZeroSigners`/`TestMultisigExportDelete`/`TestMultisigSignProgram` (kmd multisig), `TestKeysWithoutStateProofKeyCanRegister` (pre-state-proof-mandate keyreg acceptance), `TestMasterKeyGeneratePastImportedKeys` (kmd MDK-derivation-past-imports), `TestLeaseRegressionFaultyFirstValidCheckOld_2f3880f7`/`...New_2f3880f7`, `TestClientRejectsBadFromAddressWhenSending`/`...ToAddress`/`...ForWhichItHasNoKey`, `TestSendingTooMuchErrs`/`TestSendingTooLittleToEmptyAccountErrs`, `TestAssetValidRounds`, and `TestCloseOnError` are now matched or matched-1:many — all with no underlying bug found except one: writing `TestGroupTransactions`/`TestGroupTransactionsSubmission` surfaced a real gap in pool-admission group validation (a lone escaped member of a multi-txn atomic group is wrongly accepted rather than rejected), filed separately as issue #1034 per this issue's acceptance criteria rather than fixed inline. `TestSimulateStartRound` is now also closed: the simulate engine gained a minimal `dbRound`-equivalent (`LedgerStore::earliest_round`) driven by the follower node's sync round, giving it a distinct "round before dbRound" (pruned-history) error separate from "no such round at all" — see the row above for the exact scope of what is and isn't modeled.
