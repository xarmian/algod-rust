## Gaps summary

- **Fuzzer network-condition filters not ported**: no bandwidth-limiting filter (`TestBandwidthFilter`, `TestManyBandwidthFilter`, `TestNetworkBandwidth`), no message-decoder/garbling filter equivalent (`TestMessageDecoderFilter`), and no network-scale growth or regossip-elimination measurements (`TestUnstakedNetworkLinearGrowth`, `TestStakedNetworkQuadricGrowth`, `TestRegossipinngElimination`). algod-rust's `fuzzer_smoke.rs`/`algo-agreement-fuzz` only implement drop/duplicate/reorder/crash filters.
- **Full-stack gossip network integration**: `TestNetworkImplFullStackLong`/`Quick` and `TestNetworkImpl` (agreement/gossip) have no byte-for-byte Rust port; `algo-network`'s relay/tx-propagation integration tests cover the mechanics but not the same multi-node stress scenario.
- **Player state-machine edge cases**: a large block of `player_test.go` scenarios have no Rust equivalent — offset-start rounds, late block proposals in period 0, several ISV/ICV (issue-soft-vote / issue-cert-vote) sub-cases, bottom-bundle proposal, own/future-round proposal-payload propagation, malformed-bundle disconnects, bundle/payload/pipelined verification requests, pipelined-threshold handling, and several named regression tests (`8ba23942`, `RejectsCertThresholdFromPreviousRound`, `CertThresholdDoesNotBlock[FuturePeriod]`, `CertThresholdCommitsFuturePeriodIfAlreadyHasBlock`, `PayloadAfterCertThresholdCommits`, `AlwaysResynchsPinnedValue`).
- **Credential-arrival-history retention across periods**: all 14 `TestPlayerRetains*ReceivedValidatedAt*` scenarios (OneSample/PP/AVPP/HistoryWindow variants) are untested at the player-integration level in Rust, even though the underlying `CredentialArrivalHistory` data structure is thoroughly unit-tested in `types.rs`.
- **Service-level fast-recovery and regression scenarios**: no Rust tests for fast-recovery (`DownEarly`, `DownMiss`, `Late`, `Redo`), late-cert bug, recover-both-quorums, slow-payload pre/post-deadline, large-periods, protocol-upgrade-mid-consensus, certificate-stall-avoidance, or the `8ba23942` wrong-period payload-verification-cancellation regression.
- **msgp_gen codec coverage gaps**: several Go-internal state/testing types have no dedicated Rust codec/roundtrip test at all — `ConsensusVersionView`, `freshnessData`, `proposalTrackerContract`, `proposalVoteCounter`, `voteTrackerContract`. A larger set (`Deadline`, `blockAssembler`, `message`, `messageEvent`, `nextThresholdStatusEvent`, `proposalManager`, `proposalSeeker`, `proposalStore`, `proposalTable`, `thresholdEvent`, `voteAggregator`, `voteTracker`) are covered only by behavior-level unit tests rather than full randomized msgpack-roundtrip parity tests akin to Go's auto-generated ones.
- **Minor standalone gaps**: `TestSortProposalValueLess` — `ProposalValue` has no `Ord`/`Less` implementation in Rust at all (only used by go for canonical msgpack map-key sorting of `proposalValue`-keyed maps like `ProposalStore.Assemblers`/`voteTracker.Counts`; needs investigation into whether Rust's map encoding for those types already achieves canonical ordering some other way before assuming this is a real gap). ~~`TestProposalCarriesOversizedTxnGroup`~~ **fixed** (PR #857) — this one *was* a real bug, not just a missing test (`detect_validation_groups` had no group-size bound). ~~`TestProposalManagerRejectsUnknownEvent`~~ **fixed** (PR #858). `TestSampleIndexIsValid`/`TestLowerBound` were already matched via behavior-level tests; PR #859 additionally pinned their underlying constant invariants as compile-time `const` assertions. `TestPseudonodeNonEnqueuedTasks` (requires a real async execpool/backlog-overflow harness) remains untested.
