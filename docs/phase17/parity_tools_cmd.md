## Gaps summary

- **`algokey pq` (post-quantum standalone account-key CLI) — closed (issue #820).** `algokey-rust` now has a full `pq generate/info/import/sign/sign-program/check-address` subcommand family (`crates/tools/algokey-rust/src/commands/pq/`), distinct from participation-key Falcon material (`part generate`/`part info`). Of the 30 upstream tests, 22 are `matched-1:1`/`matched-1:many`, 7 are `partial` (mostly the `--mnemonic`-path and randomized-encoding rows — the underlying code path is covered but not through the exact same command/fuzz surface Go tests), and 1 (`TestPQDecodePrivateKeyRejectsMnemonic`) is `missing-test`.
- **Operator/health-monitoring daemons not ported.** `algoh` (block-stall/health watcher, 8 tests), `catchupsrv` (catchpoint-file HTTP server, 3 tests), `tools/debug/algodump` (vpack wire-message dump, 2 tests), `tools/debug/logfilter` (1 test), and `tools/network/telemetryURIUpdateService` (1 test) have no algod-rust equivalents; `capture.rs`/`observe.rs`/`autopsy.rs` cover offline traffic inspection but not these specific live-operator tools.
- **Private-network deployment tooling not ported.** `gen` (4 tests), `netdeploy` (8 tests), and `netdeploy/remote` (3 tests) — go-algorand's genesis/root-key generation and multi-node network-template deployment for private test networks — have no Rust equivalent; algod-rust's `docker-compose.localnet-rust.yml` + `gen-localnet-genesis.sh` play the same operational role but are untested shell/YAML, not Rust code with tests. `algo-ledger/src/genesis.rs` covers genesis.json *parsing/validation* only, so the `TestGenesisJsonCreation`/`TestGenerateGenesis`/`TestValidate` rows are marked partial rather than not-implemented.
- **`tools/block-generator` (offline synthetic-block load-test tool) — 28 tests, fully missing.** algod-rust's `loadgen.rs` is a much narrower *live* TPS-submission tool (payments only, no offline block-DB writing, no weighted multi-txn-type selection, no HTTP control server); it does not substitute for block-generator's `generator`/`runner` packages.
- **`tools/network/dnssec` (27 tests) — out-of-scope by design, not a gap.** algod-rust's `srv_resolver.rs` delegates DNSSEC validation to the `hickory-resolver` crate (`opts.validate = true`) instead of hand-rolling RRSIG verification/trust-chain logic, so there is no first-party DNSSEC implementation to unit-test; the SRV-priority sorting and resolver-selection tests in the sibling `tools/network` package (non-dnssec) do have partial coverage via `srv_resolver.rs`'s own tests and `dns_integration.rs`.
- **`heartbeat` service — closed (issue #820).** algod-rust now has an autonomous heartbeat service (`bin/algod-rust/src/commands/heartbeat_service.rs`) that watches locally-held participation keys each round and proactively sends a fee-exempt heartbeat when the account they participate for is under an active challenge. The old blanket `hb`-transaction rejection in `participate.rs`'s block evaluator (which would have silently discarded any heartbeat the service submitted) was also fixed as part of the same issue.
- **`libgoal` app-call resource resolution (`TestForeignResolution`, `TestAccessResolution`) — closed end-to-end (issue #820 algorithm, issue #888 slice 1 ABI subsystem, issue #888 slice 2 CLI wiring).** `crates/tools/goal-rust/src/resource_resolution.rs` ports `attachForeignRefs`/`attachAccessList`/`attachReferences`/`maybeAppend` test-for-test. `crates/core/algo-abi` (issue #888 slice 1) provides the full ARC-4 ABI type system — type parsing, JSON unmarshaling, binary encode/decode, method-selector computation, `Method`/Contract-JSON signature parsing, and the `parseMethodArgJSONtoByteSlice` more-than-15-args tuple-bundling rule. Issue #888 slice 2 added the actual `goal-rust app call`/`app method` CLI subcommands (`crates/tools/goal-rust/src/cmd/app.rs`, `crates/tools/goal-rust/src/groups/app.rs`) gluing both pieces together: `apps.AppCallBytes`-form (`encoding:value`) argument parsing, `--box`/`--holding`/`--local`/`--app-account`/`--foreign-app`/`--foreign-asset`/`--empty-refs`/`--access` ref-flag parsing, ARC-4 method-arg splitting (transaction / reference / plain-ABI), reference-arg index resolution, transaction-arg group splicing, a new `algo_txn_pipeline::ApplicationCallBuilder`, signing/submission through the existing `goal-rust` client/kmd pathway, and `"method ... succeeded with output: ..."` return-value decoding/reporting. `app create`/`update`/`delete`/`optin`/`closeout`/`clear`/`read`/`info`/`box info`/`box list` remain unimplemented (out of this issue's scope; each is a smaller, independent follow-up).
- **Go-specific dev tooling, correctly out-of-scope:** `cmd/algofix` (AST rewriter), `cmd/partitiontest_linter`, `tools/x-repo-types` (cross-repo Go type-graph analyzer), `netdeploy/remote` and `test/netperf-go/puppeteer` (internal load-test harnesses) — none have a meaningful Rust analog to build or test.
- **Missing-test / thin-coverage items worth closing:** `TestValidRounds` → `clerk.rs::compute_validity` has no direct unit test; `TestUnicodePrintable` and `TestParseRekey` have no located Rust counterparts at all despite adjacent functionality (`--rekey-to` handling) existing.
