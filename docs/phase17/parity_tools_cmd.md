## Gaps summary

- **`algokey pq` (post-quantum standalone account-key CLI) — closed (issue #820).** `algokey-rust` now has a full `pq generate/info/import/sign/sign-program/check-address` subcommand family (`crates/tools/algokey-rust/src/commands/pq/`), distinct from participation-key Falcon material (`part generate`/`part info`). Of the 30 upstream tests, 22 are `matched-1:1`/`matched-1:many`, 7 are `partial` (mostly the `--mnemonic`-path and randomized-encoding rows — the underlying code path is covered but not through the exact same command/fuzz surface Go tests), and 1 (`TestPQDecodePrivateKeyRejectsMnemonic`) is `missing-test`.
- **Operator/health-monitoring daemons — now ported.** `algoh` (block-stall/health watcher, 8 tests, issue #966, `bin/algod-rust/src/commands/health_monitor.rs`) and `catchupsrv` (catchpoint-file HTTP server, 3 tests, issue #969, `bin/algod-rust/src/commands/catchupsrv.rs`) are `docs/PROJECT_SCOPE.md` Tier 2 "power-user/ops" tools that both now have algod-rust equivalents (`algod-rust health-monitor` / `algod-rust catchupsrv`), on top of the offline traffic inspection `capture.rs`/`observe.rs`/`autopsy.rs` already covered. `algoh`'s process-supervision half (spawning/restarting a child `algod` binary, `deadman.go`'s watchdog restart, telemetry/log upload) is deliberately not ported — algod-rust's node serves its own REST API in-process rather than being externally supervised the way go's split `algod`/`algoh` binaries are, so there is no child process for a Rust equivalent to launch or kill; the state-machine/telemetry half the 8 listed tests actually cover is fully ported. `tools/debug/algodump` (vpack wire-message dump, 2 tests) and `tools/debug/logfilter` (1 test) remain deliberately not filed — niche dev-debug tooling with no PROJECT_SCOPE tier assignment and lower value now that the vpack codec itself is fully ported (#817/#925); `tools/network/telemetryURIUpdateService` (1 test) is reclassified `out-of-scope` below (no telemetry subsystem exists to feed it, same reasoning as `parity_util.md`'s `TestUUID` row).
- **Private-network deployment tooling — reclassified `out-of-scope`, not a gap.** `gen` (4 tests) and `netdeploy`/`netdeploy/remote` (11 tests) are `docs/PROJECT_SCOPE.md`'s explicit Tier 3 "internal release/test infra (not required for drop-in)" — go-algorand's genesis/root-key generation and multi-node network-template deployment tooling for private test networks. algod-rust's `docker-compose.localnet-rust.yml` + `gen-localnet-genesis.sh` already play the same operational role. `algo-ledger/src/genesis.rs` covers genesis.json *parsing/validation* only (a separate, in-scope concern), so `TestGenesisJsonCreation`/`TestGenerateGenesis`/`TestValidate` stay `partial` rather than `out-of-scope`.
- **`tools/block-generator` (offline synthetic-block load-test tool) — 30 tests, reclassified `out-of-scope`, not a gap.** Same Tier 3 reasoning as `gen`/`netdeploy` — this is go-algorand's `loadgenerator`-equivalent internal load-test infra, explicitly not required for drop-in. algod-rust's `loadgen.rs` is a narrower, in-scope *live* TPS-submission tool (operator load smoke-testing) serving a different purpose, not a substitute for block-generator's offline `generator`/`runner` packages.
- **`cmd/updater` (self-updater binary) — reclassified `out-of-scope`.** Tier 3 per `docs/PROJECT_SCOPE.md`; algod-rust ships no self-updater and isn't required to.
- **`tools/network/dnssec` (27 tests) — out-of-scope by design, not a gap.** algod-rust's `srv_resolver.rs` delegates DNSSEC validation to the `hickory-resolver` crate (`opts.validate = true`) instead of hand-rolling RRSIG verification/trust-chain logic, so there is no first-party DNSSEC implementation to unit-test; the SRV-priority sorting and resolver-selection tests in the sibling `tools/network` package (non-dnssec) do have partial coverage via `srv_resolver.rs`'s own tests and `dns_integration.rs`.
- **`cmd/algocfg` (config get/set/profile CLI) — closed (issue #973).** `algod-rust algocfg get/set/string/delete/profile {list,print,set}` (`bin/algod-rust/src/commands/algocfg.rs`) reads/writes `<data-dir>/config.json` via the existing `algo_config::Local`/`save_non_default_to_path` machinery (Phase 16), with the field lookup/parse/reset/profile-application logic itself in `algo_config::algocfg` (`crates/node/algo-config/src/algocfg.rs`) — a reflection-free port of go's `serializeObjectProperty`/`setObjectProperty`/`copyObjectProperty`/`getConfigForArg`, since Rust has no `reflect.FieldByName` equivalent. All 8 of go's named profiles are ported; `algocfg string` is an algod-rust-only addition (shell-quoted `get`).
- **`heartbeat` service — closed (issue #820).** algod-rust now has an autonomous heartbeat service (`bin/algod-rust/src/commands/heartbeat_service.rs`) that watches locally-held participation keys each round and proactively sends a fee-exempt heartbeat when the account they participate for is under an active challenge. The old blanket `hb`-transaction rejection in `participate.rs`'s block evaluator (which would have silently discarded any heartbeat the service submitted) was also fixed as part of the same issue.
- **`libgoal` app-call resource resolution (`TestForeignResolution`, `TestAccessResolution`) — closed end-to-end (issue #820 algorithm, issue #888 slice 1 ABI subsystem, issue #888 slice 2 CLI wiring).** `crates/tools/goal-rust/src/resource_resolution.rs` ports `attachForeignRefs`/`attachAccessList`/`attachReferences`/`maybeAppend` test-for-test. `crates/core/algo-abi` (issue #888 slice 1) provides the full ARC-4 ABI type system — type parsing, JSON unmarshaling, binary encode/decode, method-selector computation, `Method`/Contract-JSON signature parsing, and the `parseMethodArgJSONtoByteSlice` more-than-15-args tuple-bundling rule. Issue #888 slice 2 added the actual `goal-rust app call`/`app method` CLI subcommands (`crates/tools/goal-rust/src/cmd/app.rs`, `crates/tools/goal-rust/src/groups/app.rs`) gluing both pieces together: `apps.AppCallBytes`-form (`encoding:value`) argument parsing, `--box`/`--holding`/`--local`/`--app-account`/`--foreign-app`/`--foreign-asset`/`--empty-refs`/`--access` ref-flag parsing, ARC-4 method-arg splitting (transaction / reference / plain-ABI), reference-arg index resolution, transaction-arg group splicing, a new `algo_txn_pipeline::ApplicationCallBuilder`, signing/submission through the existing `goal-rust` client/kmd pathway, and `"method ... succeeded with output: ..."` return-value decoding/reporting. Issue #962 (slice 1): `app box info`/`app box list` (`crates/tools/goal-rust/src/cmd/app.rs`'s `run_box_info`/`run_box_list`, `crates/node/algo-rest-client`'s `get_application_box_by_name`/`get_application_boxes_page`) and `encode_bytes_as_app_call_bytes` (`crates/tools/goal-rust/src/formatting.rs`, `TestBytesToAppCallBytes`) are now implemented. `app create`/`update`/`delete`/`optin`/`closeout`/`clear`/`read`/`info` remain unimplemented — tracked as a follow-up to issue #962.
- **Go-specific dev tooling, correctly out-of-scope:** `cmd/algofix` (AST rewriter), `cmd/partitiontest_linter`, `tools/x-repo-types` (cross-repo Go type-graph analyzer), `netdeploy/remote` and `test/netperf-go/puppeteer` (internal load-test harnesses) — none have a meaningful Rust analog to build or test.
- **Missing-test / thin-coverage items — closed (issue #965).** `TestDeterminePathToSourceFromSourceMap` (TEAL source-map path resolution), `TestGetMissingCatchpointLabel` (`node.rs` catchpoint-label fetch+validate helper), `TestValidRounds` (`clerk.rs::compute_validity`'s full case table), `TestUnicodePrintable`, and `TestParseRekey` all now have direct-ported Rust unit tests (`crates/tools/goal-rust/src/cmd/clerk.rs`, `crates/tools/goal-rust/src/cmd/node.rs`, `crates/tools/goal-rust/src/formatting.rs`).
