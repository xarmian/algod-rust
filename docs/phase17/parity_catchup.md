## Gaps summary

- **Peer selection and ranking algorithm (issue #819, standalone module) — wired into live fetch paths (issue #901):** `crates/node/algo-network/src/peer_ranker.rs` is a direct port of go's `peerSelector`/`classBasedPeerSelector` (`catchup/peerSelector.go`, `catchup/classBasedPeerSelector.go`) — per-peer download-duration ranking (`PeerRanker`), penalty/eviction/upgrade bookkeeping (`HistoricStats`), and per-peer-class tolerance factors (`ClassBasedPeerSelector`/`WrappedPeerSelector`). This closes 21 of the 26 `peerSelector_test.go`/`classBasedPeerSelector_test.go` rows (5 of the 21 remain `partial`, where go's test drives a long randomized run rather than a deterministic assertion; `TestPeerSelector_PeerAddress` is not portable by design since this module has no live-network dependency to extract an address from). Issue #901 added `create_peer_selector` (mirroring go's `createPeerSelector` 4-class topology) and wired it into `GossipBlockSource`'s block-fetch peer selection (`crates/node/algo-rest-client/src/gossip_block_source.rs`), replacing round-robin, and added `RankedCatchpointSource` (`crates/node/algo-rest-client/src/ranked_catchpoint_source.rs`), wired into `AlgodSyncBackend::download_catchpoint` (`bin/algod-rust/src/commands/catchpoint_sync.rs`), replacing the single-source-only `CatchpointDownloader` call. Both feed observed download duration/failure back into the ranker after every fetch, mirroring go's `peerSelector.rankPeer`/`peerDownloadDurationToRank` call sites. `TestCreatePeerSelector` now matches; issue #917 added a `check_ledger_download` pre-flight probe stage to `RankedCatchpointSource` (mirroring go's `checkLedgerDownload`/`headLedger`), so `TestCatchpointServicePeerRank` is now `matched-1:many` (see above) — algod-rust still has no persisted, resumable `CatchpointCatchupState` machine, so this remains a test-behavior match rather than a full architecture port.
- **No staged `CatchpointCatchupService` with peer coordination:** go's `catchup/catchpointService.go` staged download pipeline (`processStageLatestBlockDownload`, `processStageBlocksDownload`, and the separate up-front `checkLedgerDownload` HEAD-probe stage) has no direct counterpart. `RankedCatchpointSource` (issue #901) ranks peers directly around the download attempt itself rather than a distinct probe stage — a peer that fails is deprioritized on retry, but there is no discrete multi-stage pipeline with per-stage peer coordination.
- **Architectural difference, not a gap:** algod-rust's `CatchupService` (`crates/core/algo-ledger/src/catchup_service.rs`) intentionally mirrors only go's certificate-driven `syncCert`/`fetchRound` path per its own doc comment, rather than the full peer-selector-backed range-sync pipeline in `catchup/service.go`; several "partial" rows above stem from this narrower scope rather than an unaddressed bug. Likewise `TestUGetBlockUnsupported` is out-of-scope because algod-rust's statically-typed per-transport fetchers (`HttpBlockFetcherSource`, `block_fetcher.rs`) have no dynamic peer-type fallback to fail on.
- **`TestSyncRound`** is matched not inside a catchup-service unit test but via algod-rust's REST v2 `/v2/ledger/sync` endpoint tests (`get_sync_round_*`, `set_sync_round_*`, `unset_sync_round_success` in `algo-rest-api`), since algod-rust exposes disable/enable-sync-round control at the API layer.
