- **Peer selection and ranking algorithm (issue #819, resolved as a standalone module):** algod-rust now has `crates/node/algo-network/src/peer_ranker.rs`, a direct port of go's `peerSelector`/`classBasedPeerSelector` (`catchup/peerSelector.go`, `catchup/classBasedPeerSelector.go`) — per-peer download-duration ranking (`PeerRanker`), penalty/eviction/upgrade bookkeeping (`HistoricStats`), and per-peer-class tolerance factors (`ClassBasedPeerSelector`/`WrappedPeerSelector`). This closes 21 of the 26 `peerSelector_test.go`/`classBasedPeerSelector_test.go` rows (5 of the 21 remain `partial`, where go's test drives a long randomized run rather than a deterministic assertion; `TestPeerSelector_PeerAddress` is not portable by design since this module has no live-network dependency to extract an address from). **The module is deliberately not wired into any live fetch path** — `gossip_block_source.rs`'s round-robin selection and `catchpoint_sync.rs`'s direct HTTP/gossip fallback are unchanged, so `TestCreatePeerSelector`, `TestCatchpointServicePeerRank`, and the downstream staged-pipeline/P2P-transport gaps below remain `not-implemented` pending that integration (tracked as documented follow-up on #819; needs live multi-node testing this workflow can't safely do unsupervised).
- **No staged `CatchpointCatchupService` with peer coordination:** go's `catchup/catchpointService.go` staged download pipeline (`processStageLatestBlockDownload`, `processStageBlocksDownload`) has no direct counterpart; algod-rust's catchpoint sync (`bin/algod-rust/src/commands/catchpoint_sync.rs`) fetches the catchpoint file and subsequent blocks more directly, without discrete peer-ranked stages.
- **Protocol-switch interruption during catchup (missing-test, 4 tests):** `CatchupLedger::round_is_not_supported` (`crates/core/algo-ledger/src/catchup_service.rs:107`) and its use in `sync_cert` implement the behavior go's `TestOnSwitchToUnSupportedProtocol1-4` verify, but no algod-rust test exercises the four interruption-timing scenarios (initial loop, mid-loop, short-notice, restart-at-switch-round).
- **Missing catchup-service metrics/sizing logic:** no `SynchronizingTime()`-equivalent elapsed-duration metric, and no `lookbackForStateproofsSupport`-equivalent calculation of how many extra blocks to download to support a pending state proof.
- **Architectural difference, not a gap:** algod-rust's `CatchupService` (`crates/core/algo-ledger/src/catchup_service.rs`) intentionally mirrors only go's certificate-driven `syncCert`/`fetchRound` path per its own doc comment, rather than the full peer-selector-backed range-sync pipeline in `catchup/service.go`; several "partial" rows above stem from this narrower scope rather than an unaddressed bug. Likewise `TestUGetBlockUnsupported` is out-of-scope because algod-rust's statically-typed per-transport fetchers (`HttpBlockFetcherSource`, `block_fetcher.rs`) have no dynamic peer-type fallback to fail on.
- **`TestSyncRound`** is matched not inside a catchup-service unit test but via algod-rust's REST v2 `/v2/ledger/sync` endpoint tests (`get_sync_round_*`, `set_sync_round_*`, `unset_sync_round_success` in `algo-rest-api`), since algod-rust exposes disable/enable-sync-round control at the API layer.
