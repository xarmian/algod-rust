## Gaps summary

- **Generic `util/metrics` primitives (Counter, Gauge, TagCounter, Registry, Prometheus/OTel exporters, node_exporter arg parsing) are not ported as reusable types.** algod-rust hand-rolls Prometheus-text rendering per subsystem (`algo-agreement`'s `ParticipationMetrics`, `algo-rest-api`'s runtime/netdev process snapshots) instead of a shared `metrics.Counter`/`Gauge`/`Registry` library. Several go tests (`TestMetricCounter`, `TestCounterWriteMetric`, `TestGetValue`, `TestCounterLabels`, `TestMetricGauge`, `TestGaugeLabels`, `TestPrometheusMetrics`, `TestPrometheusHistogramMetrics`, `TestRuntimeMetrics`) have narrower partial analogues; `TestMetricCounterMixed`, `TestGetValueForLabels`, `TestSanitizePrometheusName`, `TestWriteAdd`, `TestTagCounter*` (3 tests) have none. `TestOTelPrometheusExporter`, `TestParseNodeExporterArgs`, and `TestSanitizeTelemetryName` are out-of-scope since algod-rust implements neither OpenTelemetry export nor telemetry reporting nor a `node_exporter` sidecar integration.
- **`util/db`'s generic `Accessor`/`Migration` framework has no reusable Rust equivalent** — algod-rust talks to SQLite directly via `rusqlite` inside `algo-ledger`/`algo-kmd`, with no independently-tested wrapper layer for disposal semantics, unique in-memory naming, concurrency/locking behavior (WAL vs. journal), transaction-deadline warnings, or the versioned-migration chain (`Initialize`/`Migration`/`Versioning`). Only `SetSynchronousMode` has a partial analogue (`algo-ledger/src/sqlite.rs`).
- **`util/pagedqueue` (14 tests) is entirely unimplemented** — no eval-prefetcher pipeline or pointer-stable paged-queue data structure was found anywhere in `algo-ledger`, suggesting either the prefetch-pipeline optimization itself wasn't ported, or it uses a different (untested-here) mechanism.
- **`util/rateLimit`'s `ElasticRateLimiter`/`REDCongestionManager` algorithm (10 tests) is now ported standalone** (issue #860, `crates/core/algo-pool/src/elastic_rate_limiter.rs`) but not yet wired into any live admission path — algod-rust's incoming-transaction backlog still uses a plain semaphore/bounded-channel cap (`with_async_backlog_capacity`) rather than the RED active-queue-management algorithm go-algorand uses in `txHandler.go`. algod-rust's peer-to-peer tx path is pull-based (`crates/node/algo-network/src/tx_syncer.rs`) rather than go's push-based gossip, so the inbound-flood congestion RED exists to shed has no direct reachable trigger there; the module's doc comment sketches a plausible wiring design (REST-submission admission today, peer-serving fairness for the pull path as a follow-up) for a future PR to evaluate.
- **Whole packages are out-of-scope by design**, each backed by a Rust/architecture idiom that removes the need for a port: `util/condvar` (native `Condvar::wait_timeout`), `util/execpool` (Tokio tasks/channels replace the goroutine-pool `Stream` abstraction), the top-level `List[T]` and `Set[T]` generics in `util/list_test.go`/`util/set_test.go` (standard `VecDeque`/`HashSet`), `util/s3` (AWS hosting infrastructure, not node logic), and `util/uuid` (telemetry, which isn't implemented at all).
- **`util` top-level file/OS helpers**: `IsEmpty` and `MoveFile` (and its 5 edge-case variants) are now ported to `crates/core/algo-ledger/src/catchpoint/fsutil.rs` and wired into the catchpoint writer's atomic-rename step (issue #971), closing the previous unguarded-`std::fs::rename` gap. `GetTotalMemory` (host physical memory, out-of-scope: only used by the unported `catchpointdump` bench-report tool, Tier 2/best-effort per `docs/PROJECT_SCOPE.md`) still has no ported equivalent; the closest Rust code (`current_rss_bytes` in `algo-bench`) measures a different quantity (process RSS, not host total memory).
- **Bloom filter core algorithm is well-matched** (`crates/node/algo-network/src/bloom.rs` golden-fixture tests captured directly from go-algorand output). `TestOptimal`'s FP-rate measurement, `TestBinaryMarshalLength`'s full matrix, `TestEmptyFilter`'s exhaustive truncation fuzz, and `TestBitset`'s raw 1024-bit sweep are all now ported 1:1/1:many against the real production sizing/(un)marshal/bit-indexing code. `TestMarshalJSON` and `TestBloomFilterMemoryConsumption` remain out-of-scope (no production JSON call site upstream either; no Rust benchmark-heap-accounting equivalent).
- **`util/metrics` generic primitives are out-of-scope by design** (`Counter`/`Registry`/`TagCounter`'s own reusable machinery — algod-rust hand-rolls concrete counters at each call site instead, per issues #776/#1085's established precedent). Of the five concrete `TagCounter`-backed operational metrics production go-algorand actually emits (agreement message handled/dropped-by-type, pseudonode task backlog/timeout-by-type, and txpool reeval/remember/check counters — originally a total gap alongside the already-ported gossipsub per-tag tracer, filed as issue #1134), 4 of 5 are now ported: agreement handled/dropped-by-type and txpool reeval/remember (issue #1134), plus txpool check (issue #1142 investigation → issue #1249's `pool.test()` call site → issue #1251's counter). Only pseudonode task backlog/timeout-by-type remains unported, documented as not-applicable by issue #1142 (algod-rust's synchronous `AsyncPseudonode` has no bounded backlog queue or output-timeout to instrument).
