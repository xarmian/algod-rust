## Gaps summary

- **vpack codec entirely unimplemented (24 tests, `not-implemented`)**: the whole `network/vpack` package (stateless/stateful vote msgpack compression, LRU reference table, proposal-window HPACK compression) has no Rust port. `crates/node/algo-network/src/peer_features.rs` only advertises the `avvpack*` peer-feature bits during handshake negotiation — the actual encoder/decoder is absent, per an explicit code comment ("When the avvpack codec is implemented in a future epic..."). This also drives `not-implemented` for `TestWebsocketVoteCompression`, `TestP2PVoteCompression`, `TestVoteStatefulCompressionAbortMessage`, `TestVoteStatefulVoteCompression`, `TestMakeWsPeerMsgCodec_StatefulRequiresStateless`, and `TestWsPeerMsgDataConverterConvert`.
- **libp2p stream manager is a stub (14 tests, `not-implemented`)**: `crates/node/algo-p2p/src/streams.rs` is explicitly a placeholder ("intentionally left as a stub"). This makes the entire `network/p2p/streams_test.go` + `streams_stale_test.go` family unimplemented, and cascades to everything built on top of libp2p request/response streams: `p2pMetainfo` peer-metadata exchange (`TestReadPeerMetaHeaders`, `TestWritePeerMetaHeaders`, plus the 4 `peerMetaHeaders`/`peerMetaValues` msgp_gen tests), `TestP2PHTTPHandler(AllInterfaces)`, `TestP2PwsStreamHandlerDedup`, `TestP2PRemovePeerHoldsLockAcrossUnprotect`, and the two `TestP2PMetainfo*` tests.
- **No `IdentityTracker` (4 tests, `not-implemented`)**: go's `netidentity.go` `IdentityTracker` (dedupes concurrent connections claiming the same on-chain identity) has no Rust equivalent, though the underlying challenge/response scheme (`identity.rs`) itself is thoroughly ported.
- **No connection-limit/pubsub-parameter tuning for libp2p (13 tests, `not-implemented`)**: `algo-p2p::host::P2pHost::new` builds gossipsub/connection-manager config with library defaults only. Go's `DeriveConnLimits_*` (7 tests), `TestP2PPubSubOptions`, and the `network/p2p/pubsub_test.go` `GossipSubParams*` (3 tests) family — which derive mode-specific (server/client/hybrid/DHT-provider) connection and mesh-degree limits — are entirely absent, as are the raw address-filtering helpers (`TestNetAddressToListenAddress`, `TestP2PPrivateAddresses`, `TestP2PMaNetIsIPUnspecified`, `TestP2PMakeHostAddressFilter`).
- **Small standalone utilities with no port (`not-implemented`)**: `network/connPerfMon` (6 tests, per-connection performance/throttle monitor), `network/limitcaller` (`TestRoundTrip`, outbound bandwidth-limiting `http.RoundTripper`), `network/limited_reader_slurper` (5 tests, bounded-growth body reader), `network/websocketProxy` (2 tests), `TestRequestLogger`, and `TestMetrics_PubsubTracer_TagList` (gossipsub tag-metrics tracer).
- **Phonebook/peerstore duplication collapses to one implementation (`matched-many:1`, informational, not a gap)**: go duplicates its entire role-based phonebook (`ArrayPhonebook`/`MultiPhonebook`) once under `network/phonebook` (legacy ws transport) and again under `network/p2p/peerstore` (libp2p transport) — 24 tests total. algod-rust shares a single `crates/node/algo-network/src/phonebook.rs` across both `bin/algod-rust` wiring paths, so both go packages' tests map onto the same Rust test set.
- **Missing-test pockets in otherwise-implemented areas**: message-of-interest edge cases for TX relay (`TestWebsocketNetworkTXMessageOfInterestForceTx`/`NPN`/`PN`), zero-incoming-connections listen behavior (`TestWebsocketNetworkStartZeroIncomingDoesNotListen`), forwarded-address/header-size/HTTP-client/outgoing-queue-depth checks (`TestGetForwardedConnectionAddress`, `TestMaxHeaderSize`, `TestHTTPPAddressBoundTransport`, `TestWebsocketNetworkHTTPClient`, `TestNumOutgoingPending`), self-filtering in peer lists (`TestGetPeersFiltersSelf`, `TestCapabilities_ExcludesSelf`), multiaddr↔`AddrInfo` conversion utilities (`TestPeerInfoFromAddr(s)`, `TestP2PMultiaddrConversionToFrom`), and the happy-path user-supplied-keyfile load (`TestGetPrivKeyUserSupplied`) — these have supporting production code in Rust but lack an isolated test asserting the specific scenario.
