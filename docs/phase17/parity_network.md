## Gaps summary

- **vpack codec: stateless + stateful modes ported and wired into both websocket directions (issue #817)**: `crates/node/algo-network/src/vpack.rs` ports go-algorand's `network/vpack` package in full — the stateless layer (`vpack.go`/`msgp.go`/`parse.go`, the 1-byte presence-bitmask vote compressor, PR #885) and the **stateful** layer (`dynamic_vpack.go`/`lru_table.go`/`proposal_window.go`: the 2-way set-associative LRU reference tables for `snd`/`pk`/`pk2`, the 7-entry HPACK-style proposal sliding window, and `r.rnd` delta encoding, PR #895). Both layers are verified against real (unmodified) go-algorand `network/vpack` source output: 7 stateless byte-vectors (from PR #885) plus 8 stateful byte-vectors across two multi-vote sequences, captured by running go-algorand's actual source via a small offline Go driver, not checked into either repo. A follow-up wired the codec into `ws_peer.rs`'s **outbound** (tokio-tungstenite, `connect.rs`-dialed) read/write loops (PR #915): `peer_features::advertise_vote_compression`/`stateful_table_size` port go's `wsNetwork.go` `setHeaders`/`getBestVpackTableSize` negotiation; `write_loop`'s `try_compress_vote` and `read_loop`'s VP/AV branch port go's `wsPeerMsgCodec.compress`/`decompress`; the `VP`+`0xFF` abort/renegotiation handshake (go's `network/msgCompressor.go`) is ported as `vpack::VOTE_COMPRESSION_ABORT_BYTE`/`WriteCommand::VpAbort`. A second follow-up ported the same wiring to the **inbound** (axum, `PeerHandle::new_inbound`) path: `ws_network.rs`'s `gossip_upgrade_handler` now decodes the client's `X-Algorand-Peer-Features` request header, intersects it with this node's own advertised set (mirroring `try_connect`'s established intersection pattern), and always echoes the server's own full feature set on the 101 response (mirroring go's unconditional `setHeaders(responseHeader, ...)`); `new_inbound`'s read/write loops apply the exact same compression/decompression logic as the outbound path via two new sink-agnostic helpers extracted out of the tokio-tungstenite code (`compress_outgoing_vote`, `decompress_incoming_vote`), including the `VP`+`0xFF` abort handshake via a new `send_vp_abort_axum`. **Live-cluster evidence** (`ops/mixed-cluster`, 3 go-algorand v5.0.0-stable relays + 1 algod-rust participate node, outbound-only Rust→Go gossip): all three outbound connections negotiated `avvpack,avvpack2048` (Rust's own debug log confirms `features_negotiated=PeerFeatureFlags(7)` against each relay's real HTTP response header); the Rust node's `write_loop`/`read_loop` debug logs then show real `VP`-tagged frames sent to and received from all three relays with genuine size reduction (e.g. a 626-byte raw vote → 470-byte stateless → 343-byte stateful on send, and matching shrinkage on receive down to as little as 153 bytes once LRU references kick in) over a 40-round soak with zero abort/disable events and zero Go-side agreement rejections (`malformed proposal|malformed vote|rejected block|bundle malformed`, `BadData`, equivocation) — i.e. genuine bidirectional wire-level engagement against the real go-algorand binary, not just a negotiated-but-unused feature bit. **The mixed-cluster harness structurally cannot exercise the inbound path**: `ops/mixed-cluster/docker-compose.yml`'s `rust-node-4` entrypoint passes only `--peers=go-node-1:4161,go-node-2:4161,go-node-3:4161` (outbound dial) with no `--net-address`/gossip-listen flag and no gossip port mapping — the Rust node never accepts an inbound gossip connection in this topology, so re-running the soak proves nothing new about the inbound code path. Instead, the inbound path is verified by three real (non-mocked) integration tests in `crates/node/algo-network/src/ws_network.rs` (`inbound_peer_negotiates_and_round_trips_stateful_vote_compression`, `inbound_peer_negotiates_stateless_only_when_client_omits_stateful_tier`, `inbound_response_always_advertises_full_server_feature_set`): each spins up a genuine `WebsocketNetwork` relay server bound to `127.0.0.1:0` and a genuine outbound `connect.rs::try_connect` client over a real loopback TCP connection with a real HTTP/WebSocket upgrade handshake — i.e. two independently-implemented read/write loops talking over the real wire, not a mocked transport — and assert a vote survives compression/decompression byte-for-byte in both directions, plus that the negotiated feature flags and the raw response header match go's protocol exactly. **Known limitations**: (1) stateful table-size negotiation reads the size off the already-intersected feature flags rather than reproducing Go's independent `min(ourSize, peerSize)` arithmetic (see `peer_features::stateful_table_size`'s doc comment) — behaviorally identical whenever both sides use the same (default 2048) size, as confirmed live here, but would conservatively disable stateful compression rather than negotiate a smaller common size for two real nodes configured with different nonzero sizes; this applies to both the outbound and inbound negotiation code now.
