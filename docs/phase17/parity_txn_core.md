## Gaps summary

- ~~Per-type `WellFormed()` field validation is largely absent from the mempool-admission layer.~~ **Fixed** in issue #812 (PR #837) for payment, asset transfer/config/freeze, keyreg, and state proof. `TestUnsupportedStateProof` (StateProofInterval==0 rejection) was not covered by #812's fix; **fixed** separately in issue #1078.
- ~~**No asynchronous batched-signature-verification worker pool (`StreamToBatch`) and no verified-transaction-group cache (`VerifiedTransactionCache`).**~~ **Fixed** in issue #947 (cache landed), issue #1017 (split from #947, split-cache wiring into the block-evaluator path), and issue #1043 (wiring the pool itself into the live gossip path): the cache is now wired into both real signature-verification call sites — block verification (`algo_validate::block::validate_block_with_cache`) and gossip/mempool admission (`SimpleBlockEvaluator::validate_group_stateless_inner`, `bin/algod-rust/src/commands/participate.rs`, via `PoolLedgerAdapter`'s node-wide cache) — through the shared [`verify_transaction_group_cached`](../../crates/core/algo-validate/src/verified_txn_cache.rs) helper, which also recovers a panic into an ordinary error (`TestTxnGroupRecoversPanic`). The `StreamToBatch`-equivalent async worker pool ([`algo_validate::batch_verify::BatchVerifier`](../../crates/core/algo-validate/src/batch_verify.rs)) is now wired into the live gossip path (issue #1043): [`TxTagHandler`](../../crates/node/algo-network/src/tx_tag_handler.rs) routes every inbound TX-tag group through a shared, node-wide `BatchVerifier` instance — constructed against the same `VerifiedTransactionCache` `PoolLedgerAdapter` hands the block evaluator, mirroring go's single cache/pool shared between `node.go`'s tx handler and block evaluator — *before* `pool.remember()`, rather than verifying synchronously inline via `spawn_blocking`. See [`successful_verification_routes_through_batch_verifier_then_admits_to_pool`](../../crates/node/algo-network/src/tx_tag_handler.rs), [`failed_verification_never_reaches_the_pool`](../../crates/node/algo-network/src/tx_tag_handler.rs), and [`concurrent_submissions_share_one_batch_verifier`](../../crates/node/algo-network/src/tx_tag_handler.rs) for the wiring-specific regression coverage. Live mixed-cluster verification that the wiring doesn't change accepted/rejected transaction outcomes or introduce admission-latency regressions was not performed as part of #1043 (no mixed-cluster harness run in this pass) — see issue #1043 for disposition; this stays an open item rather than a silently-skipped criterion.
- ~~**JSON (non-msgpack) encoding fidelity for `Transaction`/`BoxRef` is unverified and likely diverges.**~~ **Fixed** in issue #948: `BoxRef.name` now carries a custom `serialize_with`/`deserialize_with` pair matching go's base64-in-JSON, raw-bytes-in-msgpack `BoxRef.Name []byte` encoding (`TestJsonMarshal`/`TestJsonUnmarshal`/`TestTxnJson` all now pinned — see the rows above). This was a live bug, not just latent: `POST /v2/transactions/simulate` (`algo-rest-api::handlers::simulate_transaction`) decodes JSON request bodies via `serde_json::from_value::<SignedTransaction>`, so a box-referencing simulate request submitted as JSON previously failed to decode a base64 `"n"` field.
- **Minor missing-test items worth a light pass rather than a new feature:** `LogicSig` blank/has-program predicate, `SignedTxn.HasSignature()`-equivalent covering all 6 signature categories, `SignedTxnInBlock.Hash()` pin, PQ-signature fee-contribution unit test, `ApplyData`/`EvalDelta`/`LogicSig` equality-on-near-zero-fields pins, and a `Header` field-count regression guard. These are all cases where the underlying behavior appears implemented (or trivially derivable) but lacks a dedicated unit test — cheap wins if a follow-up issue batch is filed.
