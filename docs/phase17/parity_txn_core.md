## Gaps summary

- ~~Per-type `WellFormed()` field validation is largely absent from the mempool-admission layer.~~ **Fixed** in issue #812 (PR #837) for payment, asset transfer/config/freeze, keyreg, and state proof. `TestUnsupportedStateProof` (StateProofInterval==0 rejection) remains `not-implemented` — not covered by #812's fix.
- ~~**No asynchronous batched-signature-verification worker pool (`StreamToBatch`) and no verified-transaction-group cache (`VerifiedTransactionCache`).**~~ **Partially fixed** in issue #947: a `VerifiedTransactionCache`-equivalent (bounded, bucket-cycling, pinning-aware cache keyed by transaction ID plus a verification-context equality check) now exists at [`algo_validate::verified_txn_cache`](../../crates/core/algo-validate/src/verified_txn_cache.rs), with the `verifiedTxnCache_test.go` cases above ported and passing. It is **not yet wired** into the gossip/mempool-admission or block-verification call paths (so no cache hits are actually skipped in the hot path yet), and the `StreamToBatch`-equivalent asynchronous worker pool (batched dispatch, graceful shutdown, cancellation, panic/error isolation — `data/transactions/verify/txnBatch_test.go`'s 15 tests, plus the `TestTxnGroupCacheUpdate*` family and `TestTxnGroupRecoversPanic` in `txn_test.go`, all still `not-implemented` above) remains open. Both remaining pieces are tracked in follow-up [issue #1017](https://github.com/xarmian/algod-rust/issues/1017) (split from #947).
- ~~**JSON (non-msgpack) encoding fidelity for `Transaction`/`BoxRef` is unverified and likely diverges.**~~ **Fixed** in issue #948: `BoxRef.name` now carries a custom `serialize_with`/`deserialize_with` pair matching go's base64-in-JSON, raw-bytes-in-msgpack `BoxRef.Name []byte` encoding (`TestJsonMarshal`/`TestJsonUnmarshal`/`TestTxnJson` all now pinned — see the rows above). This was a live bug, not just latent: `POST /v2/transactions/simulate` (`algo-rest-api::handlers::simulate_transaction`) decodes JSON request bodies via `serde_json::from_value::<SignedTransaction>`, so a box-referencing simulate request submitted as JSON previously failed to decode a base64 `"n"` field.
- **Minor missing-test items worth a light pass rather than a new feature:** `LogicSig` blank/has-program predicate, `SignedTxn.HasSignature()`-equivalent covering all 6 signature categories, `SignedTxnInBlock.Hash()` pin, PQ-signature fee-contribution unit test, `ApplyData`/`EvalDelta`/`LogicSig` equality-on-near-zero-fields pins, and a `Header` field-count regression guard. These are all cases where the underlying behavior appears implemented (or trivially derivable) but lacks a dedicated unit test — cheap wins if a follow-up issue batch is filed.
